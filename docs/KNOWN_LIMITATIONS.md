# Known limitations of Transcriber 2.1.4

This stage delivers a substantial desktop/workspace and service-layer expansion. It is not yet the complete production audio/AI suite described in the product roadmap. The following limitations are intentional and must remain visible until validated implementations replace them.

- **No incremental live ASR.** Live Recording captures microphone audio, supports device selection, pause/resume and saving, stores independent recording history, then can hand the saved file to transcription. It does not stream partial Whisper segments while recording.
- **Batch jobs are sequential and session-scoped.** The Batch page supports multi-file queueing, per-file progress, pause/resume/cancel, retry of failed/cancelled items and subtitle export. The queue is not persisted for restart recovery and does not run multiple ASR model instances in parallel.
- **Faster-Whisper and Google Cloud Speech-to-Text V2 are the integrated ASR engines.** Faster-Whisper remains the only local model-backed engine. Google Cloud V2 is an explicit, consent-gated online adapter using Application Default Credentials and synchronous chunk requests; it does not use a user-configured GCS bucket or implement long-running GCS batch recognition. Vosk, whisper.cpp and WhisperX are not wired into the primary ASR workflow.
- **Generic multi-model runtime is not yet the application's global model manager.** The new runtime supports a configurable 1–10 model ceiling, load/unload/pin, RAM/VRAM budgets, lazy loading and LRU eviction for registered adapters. No claim is made that ten useful models can fit in a given machine; actual adapters and trustworthy memory estimates are required. Existing Faster-Whisper still uses its own single-active lifecycle.
- **Diarization is not implemented.** Speakers can be assigned and edited manually and speaker labels are preserved in document/subtitle data. Automatic speaker counting, embedding, clustering, merge/split speaker identity tools and diarization inference are not yet available.
- **Wake-word recognition is experimental and opt-in.** An optional Vosk microphone adapter can listen locally for the configured phrase and capture a command through a local recognizer. Persian and English false-positive/false-negative rates have not been benchmarked; exact phrase recognition depends on the selected Vosk model and vocabulary. The openWakeWord pretrained models are not assumed to support Persian. No model weights are bundled, and the microphone is not opened until the user explicitly enables local wake detection. Push-to-talk currently uses the active local voice input session.
- **Voice submission is opt-in, not a complete spoken conversation.** Recognized text is placed in the Agent prompt field. Users can keep review-before-send (default) or explicitly enable automatic submission to the connected OpenCode session. TTS response playback, interruption handling, reliable ACP reconnection and measured multilingual wake-word accuracy are not implemented.
- **OpenCode integration requires a separately installed OpenCode executable.** The ACP client supports stdio startup, initialize, persistent new/load session, prompt, streaming notifications and cancellation. It does not yet implement transparent auto-reconnect/retry after process failure. A single session cannot execute concurrent prompts.
- **MCP exposes a compact dynamic action surface.** The standalone stdio MCP server offers state, action discovery and registered action execution over per-user authenticated local IPC. Many possible product operations are not yet registered as Agent actions; unsupported features cannot be invoked just because the UI mentions them. The GUI must be running for application state and actions to be available.
- **Agent permissions are conservative.** Read-only and transcript editing are enabled by default. Settings, audio capture, file export, model management and destructive actions require separate permission enablement. Destructive actions must additionally use the GUI approval callback. The current registered action set is smaller than the full permission taxonomy.
- **Audio cleanup is a non-destructive FFmpeg output workflow.** It writes a new file and protects the source. The current denoising filter is a one-pass spectral filter, not Audacity-style noise-profile learning; there is no non-destructive multi-clip timeline, spectral repair UI, A/B loop, or spectrogram editor.
- **Video transcription uses the first audio track.** Supported audio/video containers are validated through PyAV before recognition; Faster-Whisper, Vosk and the consent-gated Cloud path then decode or extract the first audio stream. Multiple audio tracks are counted and the first is used; there is no track selector, synchronized picture preview or subtitle burn-in.
- **Subtitle Studio covers text/timing, not full video production.** SRT, WebVTT, ASS and SSA parsing/export, timing offsets, frame-rate scaling, minimum gaps, overlap and reading-speed checks are implemented. Visual waveform/video point sync, subtitle styles preview, spell check, translation and OCR are not.
- **AI Studio is not a full local/cloud text-intelligence provider.** OpenCode can receive user-authored prompts and is given the registered Transcriber actions through MCP. Dedicated summarization, translation, glossary, chapter generation, provider selection, cost/retention controls and structured AI preview/diff workflows are future work.
- **WAV-only microphone output.** Native 16-bit PCM WAV is the only advertised recording format. MP3, M4A, AAC, FLAC and Opus output require an encoder capability check and a separately implemented finalization path.
- **English UI only.** Persian transcription/model options are possible where the selected model supports them, but translated application catalogs and RTL workspace layouts are not included.
- **No signed installers or packaged release binaries have been produced.** A Python wheel was built as a packaging check and includes the selected Lucide assets. PyInstaller bundles, code signing and OS-specific release validation remain release work.
- **Qt runtime validation is pending.** This development environment has no PySide6 installation, so the real GUI smoke test is skipped. Compile checks and non-Qt unit/integration tests pass, but the actual window, microphone, playback devices, CUDA inference, a real OpenCode installation and MCP SDK runtime still need validation on a target desktop.

Do not promote a feature from this list to “implemented” based only on an adapter interface, model catalog entry, UI label or roadmap entry.
